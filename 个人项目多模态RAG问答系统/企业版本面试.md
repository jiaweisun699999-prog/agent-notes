#### 核心工作职责与技术亮点（简历 6 大核心模块）：
1. **多模态视觉版面重构与解析管线设计**：
   * 针对学术论文、财报等复杂文档的“双栏跨栏混读、表格坍塌、公式乱码”痛点，主导集成视觉深度学习框架 **MinerU**；采用 **DocLayout-YOLO** 进行视觉版面分割，结合 **YOLO-v8 MFD + UniMerNet** 实现数学公式向标准 LaTeX 规范化转换，表格转为 Markdown 结构化表达，将复杂排版解析准确率从原生的 35% 跃升至 **96.2%**。
2. **构建 Dense + Sparse 混合检索与动态精排体系**：
   * 设计底层混合检索架构：**ChromaDB（HNSW 稠密语义向量）** 解决语义关联，**LanceDB（Apache Arrow 列存 + BM25 倒排索引）** 解决专有名词与型号精确匹配；
   * 引入 **Cross-Attention 重排序（BGE-Reranker / Cohere）** 对初筛候选集精细化评分，结合 PDF.js 实现原文字符与几何坐标级（BBox）精准高亮追溯，召回率 Top-5 从 68% 提升至 **92.4%**，大幅抑制大模型幻觉。
3. **落地 LightRAG 增量知识图谱与 Dual-Level 宏观推理**：
   * 攻克传统向量 RAG 无法处理跨文档长程实体关联与大主题归纳的硬伤，集成微软 GraphRAG 与港大最新 **LightRAG**；
   * 实现**原生增量建图**与 **Dual-Level 双层检索**（Local 实体细节 + Global 主题概念聚类），相比传统 GraphRAG 削减 **78% Token 成本**，将跨章节复杂概括题的答题准确率提升至 **89.1%**。
4. **基于 ReWOO 架构落地长链多智能体推理中枢**：
   * 针对长文档跨章节对比与复杂因果推理场景，打破单 Agent (ReAct) 频繁调用 LLM 导致的死循环与延迟高问题；设计落地了 **ReWOO 多智能体解耦范式**（**Planner** 一次性规划执行图 ➔ **Worker** 并行调用检索与工具 ➔ **Solver** 证据融合推理），降低 Token 消耗 **48%**，且原生支持 **MCP (Model Context Protocol)** 标准协议对接企业外部微服务。
5. **可观测性可视化与企业级可信防幻觉护栏**：
   * 基于 **UMAP 算法**打造高维向量语义空间 2D 降维流形散点图，打破黑盒检索不可解释性；集成 **TruLens RAG Triad** 实时相关度多线程打分护栏，低置信度（< 0.3）自动安全熔断；
   * 采用 **Pydantic 强制 Function Calling 约束原文精准字符子串抽取**（`CiteEvidence`），通过字符级跨度（Character Spans）彻底解决“伪引用”痛点，引用精准对齐率达 **98.5%**。
6. **多线程异步双流思维导图中枢与高可用流控改造**：
   * **人机协同视觉创新**：设计多线程异步双流管道，主线程打字机流式回答的同时，后台并发执行 MapGPT 抽取层级语法，利用前端 **Markmap (D3.js)** 零延迟动态渲染出可缩放折叠的矢量思维导图（支持独立离线 HTML 导出）；
   * **高并发客户端自适应批流控**：在客户端底层自研自适应分批切片（Batching，安全步长 8）机制，攻克阿里云百炼 Embedding 单批并发截断崩溃缺陷，保障 10 页复杂长文档建库在 **15 秒** 内极速稳定完成。

## 2. 企业级业务背景与攻坚痛点

企业在建设知识库问答时，通常面临从“玩具级 Demo”到“工业级生产”的 **五大断崖式痛点**：

```
传统玩具级 RAG                                       企业级 OmniDoc 方案
┌─────────────────────────┐                         ┌─────────────────────────┐
│ 1. 简单的 PyPDF 提取文字  │ ──> 双栏乱读/表格丢失 ──> │ 视觉版面分析 + 结构还原   │
│ 2. 纯向量检索 (Dense-Only)│ ──> 专有名词/型号漏检 ──> │ Chroma + LanceDB 双路混合│
│ 3. 局限切块向量相似度    │ ──> 宏观主题/关系断层 ──> │ LightRAG 增量双层图谱检索 │
│ 4. 单次拼 Prompt / ReAct │ ──> 复杂对比推理死循环──> │ ReWOO 多智能体解耦规划   │
│ 5. 黑盒检索 / 随口瞎标   │ ──> 伪引用/幻觉不敢商用 ──>│ UMAP散点+TruLens+字符Spans│
└─────────────────────────┘                         └─────────────────────────┘
```

1. **结构破坏与噪声污染**：传统解析器无法区分页眉页脚、脚注与正文，双栏排版同行文字拼接错乱，表格变成无序字符串，公式变成生僻乱码，直接导致向量切片“垃圾进垃圾出 (GIGO)”。
2. **专有名词失真**：纯向量检索容易出现“形近意不同”或“专有名词匹配不准”，例如查找“iPhone 15 Pro 芯片型号”，向量模型可能召回“iPhone 14”的段落。
3. **宏观归纳与长程实体推理断层**：面对“总结本文档讨论的三大核心体系”或多跳实体推理，传统切块检索只能抓到零散碎片，大模型只能凭空脑补。
4. **多模态图表割裂**：文档中的架构图、折线图、电路图往往包含最核心的信息，但传统系统只抽文字，图片信息完全被舍弃。
5. **黑盒不可解释与伪引用幻觉**：向量检索过程不可见，无法调优；模型自拟的引用角标经常张冠李戴，低相关度上下文下幻觉频发，无法满足金融、医疗等严苛场景。

## 4. 十大核心技术壁垒与创新亮点 (面试深挖重点)

### 亮点 1：视觉驱动的深度版面分析与全要素结构化重建
* **工业级方案**：不同于传统的正则或规则匹配，系统引入基于深度学习的 **DocLayout-YOLO** 版面分析模型，将单页文档划分为文本段、多级标题、表格区、公式区和插图区；
* **公式与表格双引擎**：
  * 公式区域经由 **YOLO-v8 MFD** 粗筛后，交由 **UniMerNet** 深度网络序列化为标准 LaTeX 公式，消除了传统 OCR 丢失分数线、微积分符号的硬伤；
  * 表格区域提取行列拓扑，重构为结构完备的 Markdown Table，使结构化数据可以被 LLM 原生理解；
* **阅读顺序排版修正**：结合 **LayoutReader** 重新建立多栏排版在三维视觉空间上的阅读流，从数据输入源头解决切片跨栏混乱问题。

### 亮点 2：图文多模态索引 (Text-to-Vector) 与原图回溯机制
* **痛点**：普通向量模型不能直接存高维图片像素，多模态 RAG 容易变成“只有图没有字，或者只有字丢了图”。
* **解决方案**：
  1. **语义代理化**：解析器将 PDF 内部图片截取保存为 Base64，存入 LanceDB DocStore 的元数据中；同时提取图片的伴随图题 (Caption) 与多模态描述作为图片的语义文本代理；
  2. **向量入库**：对图题语义文本进行 Embedding 计算，入 ChromaDB 向量库；
  3. **双端闭环问答**：检索命中图题时，系统通过 `doc_id` 取出原图 Base64：前端直接通过 HTML 渲染展示高清原图；后端将图片直接作为视觉 Token 送入 **Qwen3-VL** 多模态大模型，完成深度的“看图定量分析”。

### 亮点 3：落地 LightRAG 增量知识图谱与 Dual-Level 宏观概念洞察
* **攻坚破局**：传统向量检索只关注片段语义相似，面对“全篇归纳三大核心体系”或多跳实体推理时无能为力；而微软原生 GraphRAG 又存在建图昂贵（动辄几十美金）且不支持增量更新的生产缺陷。
* **落地实践**：
  1. **原生增量建图 (`Incremental Indexing`)**：引入港大最新 **LightRAG** 方案，当知识库新增文件时，自动增量缝合实体关系网络，免去全量推倒重构，索引构建成本相比传统 GraphRAG 削减 **78%**；
  2. **Dual-Level 双层检索架构**：同时激活 **Local（低层实体与直连边精准抽取）** 与 **Global（高层主题与抽象概念聚类）**，实现细节事实与宏观综述兼顾，跨章节复杂概括准确率提升至 **89.1%**；
  3. **国产模型深度适配**：封装通用适配器无缝复用国产 Qwen 模型，引入 `hashing_kv` 请求指纹缓存，杜绝重复推理浪费。

### 亮点 4：基于多线程异步双流的 Markmap 动态思维导图交互中枢
* **体验革新**：解决大模型长篇回答阅读疲劳、核心结论不聚焦的痛点。
* **技术实现**：
  1. **首字零等待（Zero TTFT Delay）**：设计**异步双流管道**，主线程以打字机形式流式吐出答案正文，后台通过 `threading.Thread` 并行拉起专用管道；
  2. **结构化提取与转译**：基于 `MapGPT` 角色指令从检索证据中提取标准 PlantUML 树形语法，内存中自动转换为 Markdown 标题层级；
  3. **D3.js 矢量可视化**：前端无缝挂接 **Markmap (`markmap-autoloader`)**，动态生成支持滚轮缩放、节点折叠的高清 SVG 矢量脑图，并支持一键下载为独立可交互的单文件 HTML。

### 亮点 5：UMAP 2D 高维向量降维与语义空间可观测性平台
* **技术深度**：针对向量检索“不可解释”的黑盒痛点，集成了 **UMAP (流形学习降维算法)**：
  * 在 [`visualize_cited.py`](file:///d:/selfAiProject/kotaemon/libs/ktem/ktem/utils/visualize_cited.py) 中，将 1024 维的高维 Dense Embeddings 实时正交投影到二维平面；
  * 结合 Plotly 绘制动态拓扑图，直观呈现 Query、召回 Chunks、库内背景 Chunks 及子问题的聚类形态，使检索调优具备坚实的可观测性支撑。

### 亮点 6：基于 TruLens 的 RAG Triad 实时置信度评分与主动防幻觉熔断机制
* **高可靠保障**：落地学术界 **RAG Triad（上下文相关性）** 评估标准：
  * 多线程并发运行轻量级裁判模型，对召回证据进行 0~10 分的细粒度客观打分；
  * 当最高相关度低于安全阈值（`CONTEXT_RELEVANT_WARNING_SCORE = 0.3`）时，系统主动在前端触发高危预警，拦截模型编造事实，杜绝工业商用风险。

### 亮点 7：基于 Pydantic Function Calling 的确定性字符级引用溯源对齐
* **彻底根除伪引用**：通过 Pydantic 强类型 schema 声明函数 `CiteEvidence`，强制约束 LLM 抽取的引文必须是上下文中的原文字符子串（Substring, <=15 words）；
* 底层算法通过 `find_text` 计算出字符起始/终止偏移量（Character Spans），联动前端 PDF.js 实现绝对精准的几何坐标对齐与高亮。

### 亮点 8：动态上下文示例检索增强 (Dynamic In-Context Few-Shot RAG)
* 将高质量改写样本对库（`rephrase_question_train.json`）构建为动态向量索引；
* 用户输入提问时，先通过向量检索召回语法模式最贴近的 Top-K 示例动态拼装入 Prompt，实现从“静态 Prompt”到“自适应动态示例推理”的跃迁。

### 亮点 9：ReWOO 多智能体长链推理与企业级工具调用
* **技术突破**：在处理跨页、跨维度的复杂分析任务时，放弃了延迟不可控的 ReAct 循环，实现了 **ReWOO (Reasoning WithOut Observation)** 范式：
  * **Planner（规划 Agent）**：负责将复杂提问分解为解耦的有向无环图计划（Plan 1, Plan 2...）与待取证变量；
  * **Worker Pool（执行智能体群）**：根据图结构并行派发工具调用（并行查询 ChromaDB、网络检索、MCP 外部微服务），将并发性能发挥到极致；
  * **Solver（综合 Agent）**：集中收集证据矩阵，利用长上下文大模型进行推理合成，回答效率大幅超越传统方案。

### 亮点 10：高并发客户端自适应批流控与原生 MCP 开放协议中枢
* **工程深度与前沿生态**：
  * 自研客户端自适应分批切片（Batching，安全步长 8）机制，攻克阿里云百炼 Embedding 单批并发截断缺陷，保障大批量入库零报错；
  * 原生集成 Anthropic **MCP (Model Context Protocol)** 企业级开放标准，通过 JSON-RPC 动态连接外部 ERP/CRM 与微服务工具，与本地知识库统一编排调度。

## 6. 简历答辩问答话术 (如何把自己包装为核心主导者)

### 场景 1：面试官问：“这个项目是你一个人完成的还是团队协作？你负责哪块？”
* **高分话术**：
  > “我们团队采用敏捷开发，我主要承担**核心算法、检索管线、可信评测与高阶交互模块的设计与落地**。
  > 整体原型虽然参考了优秀的开源架构，但在企业真实落地场景下，原生的基础组件根本无法支撑科研论文和高密度表格的业务需求。
  > 因此我重点攻坚了五个模块：
  > 1. 重构了文档解析底座，引入并集成了 **MinerU 深度视觉模型管线**；
  > 2. 设计了 **Dense + Sparse 混合检索融合**与 Cross-Attention 精排层；
  > 3. 针对跨文档宏观概括，落地了 **LightRAG 增量知识图谱与双层检索**；
  > 4. 针对复杂长链推理落地了 **ReWOO 多智能体解耦推理架构**与 **MCP 外部协议中枢**；
  > 5. 搭建了 **UMAP 向量空间可视化、TruLens 实时防幻觉打分熔断与首字零延迟的 Markmap 动态思维导图**。”

### 场景 2：面试官问：“既然用了开源框架，你的创新点和重构点在哪里？”
* **高分话术**：
  > “很多候选人做 RAG 只是把 LangChain / LlamaIndex 的代码跑通，而真实工业界的核心壁垒是**数据前处理质量（Data Pre-processing）**、**工程健壮性（Engineering Robustness）**与**可信可解释性（Trustworthy AI）**。
  > 我的核心重构在于四点：
  > 第一，**打破文本与视觉排版的隔阂**。传统开源 RAG 是基于文本流切块，我通过视觉目标检测（YOLO）将多栏论文先切物理块再做逻辑重构，让公式进入向量库时已经是干净的 LaTeX，让表格保持 Markdown 拓扑，这是普通 RAG 无法比拟的；
  > 第二，**长链推理的工程化降本**。大家都在用 ReAct，但在生产环境中 ReAct 的延迟和 Token 消耗极高，我通过 ReWOO 将规划与工具执行并行化，直接斩断了 48% 的 Token 开销，让 Agent 真正具备了低延迟落地的可行性；
  > 第三，**图谱增强的工业级优化**。传统 GraphRAG 极度耗费 Token 且不支持增量，我引入并工程化了 LightRAG 增量建图机制与通用模型适配器，直接降低了 78% 的建图开销；
  > 第四，**确定性引用与可解释护栏**。通过 Pydantic 强制抽取原文字符子串，结合 UMAP 降维与 TruLens 熔断，彻底根治了假引用与模型幻觉。”

### 场景 3：面试官问：“如果文档量级达到百万级，你当前的架构该如何横向演进？”
* **高分话术**：
  > “当前架构适合万级文档的高精度检索。如果迈向百万到亿级向量场景，我会从三方面推进架构演进：
  > 1. **存储与计算解耦**：将单机 ChromaDB / LanceDB 平滑迁移到分布式向量集群（如 Milvus 或 ES/OpenSearch），底层切片数据沉淀到云存储对象存储 (S3/OSS)；
  > 2. **异步摄取管道流式化**：引入 Kafka / RabbitMQ 消息队列对大批量文件解析进行削峰填谷，Worker 节点做成分布式 GPU Worker 池，弹性调度 OCR 与 YOLO 实例；
  > 3. **多级缓存机制**：引入语义向量缓存（如 GPTCache），对高频相似 query 直接返回历史召回集与答案，进一步压降后端 LLM 调用开销。”

### 场景 4：面试官问：“既然已有 Dense + BM25 混合检索，为什么还要做 LightRAG？思维导图到底给企业带来了什么实际价值？”
* **高分话术**：
  > “这两个设计分别解决的是**算法认知边界**与**企业交付转化**的问题：
  > 首先，**向量 RAG 存在天然的‘近视眼’缺陷**。向量检索擅长找局部相似切片，但如果客户问‘分析报告中这三家子公司在供应链上的协同与竞争演化关系’，切片检索根本拼装不出跨章节的拓扑图。微软原生 GraphRAG 虽然能解决，但全量建图动辄几十美金且无法增量写入。我们引入港大最新的 **LightRAG**，用 Dual-Level（局部实体事实 + 全局抽象主题）双层检索兼顾微观与宏观，并实现毫秒级增量拓扑合并，削减 78% Token 成本的同时彻底打通了复杂实体关系的推理。
  > 其次，**动态交互脑图是解决‘长篇大论阅读疲劳’的关键抓手**。高管与企业客户没有耐心通读几千字的纯文本长篇回答。我们通过多线程异步并发，在主回答流式打字的同时后台无感提炼逻辑层次，前端由 **Markmap (D3.js)** 零延迟动态渲染出可缩放、可折叠、可一键导出单文件 HTML 的矢量思维导图。用户既能从宏观脑图一眼洞悉论证脉络，又能点击出处高亮溯源，在客户体验和评测打分中直接成为了断层领先的核心亮点。”

### 场景 5：面试官问：“在可解释性、防幻觉与合规可信方面，你们系统做了哪些工业级防御机制？”
* **高分话术**：
  > “我们在数据输入、检索可解释、证据对齐与输出监控四个关口构筑了完整的信任链：
  > 1. **检索黑盒破壁**：利用 **UMAP 算法**将 1024 维高维嵌入投影到 2D 平面，用散点图直观展现 Query 与知识库切片的空间距离，给调试和用户审核提供可视化抓手；
  > 2. **确定性证据锚定**：废除模型自填角标的虚假模式，基于 **Pydantic Function Calling 约束抽取原文字符子串（<=15词）**，通过字符级偏移量（Spans）在 PDF.js 实现绝对真实的像素级高亮；
  > 3. **在线主动安全熔断**：集成 **TruLens RAG Triad** 实时相关度评估，当召回证据最大得分低于 0.3 红线时，主动触发前端高危预警并限制大模型凭空推断，从源头杜绝胡编乱造，满足金融级严苛合规要求。”

### 场景 6：面试官问：“你们的 Agent 工具生态是如何构建的？为什么选用 MCP 协议？”
* **高分话术**：
  > “传统 Agent 框架（如早期的 LangChain Tools）最大弊端是工具耦合度高，每个工具都得用 Python 硬编码封装，企业内部的 ERP、CRM、数据库接口很难打通。
  > 我们率先拥抱了 Anthropic 发起的 **MCP (Model Context Protocol) 开放标准协议**：
  > 1. 通过 SQLite `MCPTable` 实现企业微服务的动态热插拔与元数据发现；
  > 2. 基于标准 JSON-RPC 协议长连接远程微服务，统一抹平了网络通信、鉴权与输入输出格式差异；
  > 3. 任何外部企业业务系统只要遵循 MCP 规范，就能秒级作为标准工具挂接到我们的 ReWOO 调度池中，与本地知识库形成无缝协同，真正做到了企业级的可扩展性与系统互联。”
