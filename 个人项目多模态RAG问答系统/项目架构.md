## 1. 项目概述

**Kotaemon** 是一款基于 RAG (Retrieval-Augmented Generation，检索增强生成) 技术的开源 Clean & Customizable 智能文档 QA 框架。它既为终端用户提供了友好的多模态 Web UI 界面，也为 AI 开发者提供了高度可扩展的 RAG Pipeline 编排底层库。

主要应用场景：
- **学术论文/长文档多模态问答**（支持提取分析论文插图、数据图表及表格）
- **混合检索与出处溯源**（提供精准的 PDF 高亮引用展示及文献定位）
- **图谱增强检索与宏观归纳**（内置 Microsoft GraphRAG 与轻量级增量 LightRAG，攻克跨篇章实体关系推理）
- **动态交互式脑图呈现**（异步双流生成 Markmap 矢量思维导图，实时梳理回答逻辑脉络）
- **可观测性与可信护栏**（集成 UMAP 2D 高维向量降维可视化与 TruLens RAG Triad 实时防幻觉打分熔断）
- **复杂推理与企业工具协同**（支持 ReWOO 代理推理与 Anthropic 原生 MCP 企业协议中枢）

## 2. 核心技术栈

### 核心语言与环境
- **Python**: `>= 3.10`
- **包管理工具**: `uv` (Rust 编写的高性能 Python 包管理器) / `pip` / `conda`

### 前端 UI 与交互
- **Gradio 4.x**: 用于快速构建高可定制化的 AI Web UI 界面。
- **PDF.js**: 内置浏览器 PDF 预览器，支持对检索引用的出处段落进行实时高亮展示。
- **Markmap (D3.js 驱动)**: 矢量思维导图（Mindmap）交互组件，支持节点缩放折叠与独立 HTML 导出。
- **Plotly & NetworkX**: 负责知识图谱拓扑网络力导向图（Spring Layout）的实时动态交互渲染。
- **UMAP (Uniform Manifold Approximation and Projection)**: 高维向量流形学习降维算法，将 1024 维 Dense Embeddings 压缩到 2D 拓扑空间散点图。

### 知识图谱与图 RAG 引擎
- **Microsoft GraphRAG**: 微软官方知识图谱方案，集成 Leiden 层次化社区发现算法与社群摘要生成。
- **LightRAG (HKUDS)**: 新一代轻量化增量知识图谱 RAG，支持 Dual-Level（局部实体 + 全局概念）检索与增量建图。

### 工作流、Agent 协议与可信评测
- **theflow**: 开发者团队自研轻量级 DAG 节点与工作流编排库（提供 `Component`, `Node`, `Param` 抽象）。
- **Model Context Protocol (MCP)**: 原生集成 Anthropic 发起的企业级标准协议，通过 JSON-RPC 动态连接外部微服务与数据库。
- **TruLens RAG Triad**: 实时防幻觉三元组评测护栏，集成多线程 LLM-as-a-judge 对召回证据进行 0~10 分细粒度置信度打分。
- **LangChain (0.2+) / LlamaIndex (0.10+)**: 底层大模型组件适配层与索引检索封装。

### 数据库与存储
- **向量数据库 (VectorStore)**: **ChromaDB**（基于 `chroma.sqlite3`，负责存储 1024 维等高维向量）。
- **文档/全文检索库 (DocStore)**: **LanceDB**（基于 Apache Arrow 格式，支持极速全文 BM25 检索与实体描述向量存储）。
- **元数据与用户数据库**: **SQLite3**（基于 SQLAlchemy / SQLModel，存储对话历史 `sql.db`、MCP 服务配置、用户权限及模型配置）。
- **图数据存储**: GraphML 拓扑文件、Parquet 列存表（Nodes, Edges, Communities）。

### 大模型 (LLM) 与嵌入 (Embedding) 引擎
- **API 云端厂商**: 阿里云百炼 (DashScope / Qwen)、OpenAI (GPT-4o / GPT-4o-mini)、Azure OpenAI、Cohere、Anthropic Claude、Google Gemini、Mistral 等。
- **本地离线模型**: Ollama (支持 `Qwen2.5`, `Llama3.1`, `Nomic-Embed-Text` 等) 及 `llama-cpp-python` (GGUF 格式)。

### 多模态与文档解析
- **PDF & 文本解析**: `PyMuPDF` (fitz), `pypdf`, `python-docx`, `openpyxl`
- **高精度论文解析**: **MinerU** (`magic-pdf`，集成 DocLayout-YOLO 版面分析、LaTeX 数学公式提取与 Markdown 表格还原)
- **多模态图表解析**: `Docling` (开源本地解析器), `Azure Document Intelligence`, `Adobe PDF Extract`, `PaddleOCR`

## 3. 整体架构设计

Kotaemon 采用了标准的 **双层解耦架构**（底层 AI 算法库 + 上层 应用产品 Web 框架）：

```
+----------------------------------------------------------------------------+
|                            Kotaemon Web App                                |
|                        (libs/ktem - 基于 Gradio)                           |
|  +------------------+  +-------------------+  +-------------------------+  |
|  |  智能问答 (Chat) |  |  文档管理 (Files) |  |  资源与设置 (Settings)  |  |
|  +------------------+  +-------------------+  +-------------------------+  |
+----------------------------------------------------------------------------+
                                     |
                                     v
+----------------------------------------------------------------------------+
|                        Kotaemon Core RAG Pipeline                          |
|                       (libs/kotaemon - 核心算法库)                          |
|  +------------------+  +-------------------+  +-------------------------+  |
|  | Base Component   |  | Index & Retriever |  |  LLM & Embedding Models |  |
|  | (theflow 节点)   |  | (Chroma/LanceDB)  |  | (DashScope/OpenAI/etc.) |  |
|  +------------------+  +-------------------+  +-------------------------+  |
+----------------------------------------------------------------------------+
```

### 3.1 底层算法库 (`libs/kotaemon`)
提供纯粹的 Python 算子与 RAG 组件：
- `kotaemon.base`: 基础节点 `BaseComponent` 与 `Document` 数据结构。
- `kotaemon.embeddings`: 统一的嵌入模型调用接口（如 `OpenAIEmbeddings`, `FastEmbedEmbeddings`）。
- `kotaemon.llms`: 统一的大模型对话接口（如 `ChatOpenAI`, `ChatOllama`）。
- `kotaemon.storages`: 向量存储库与文档存储库抽象。
- `kotaemon.indices`: 包含 `FullQAPipeline`、`AnswerWithContextPipeline` 等检索问答管道。

### 3.2 应用与界面层 (`libs/ktem`)
基于 Gradio 构建的完整 Web 应用程序：
- `ktem.app`: 应用主入口类 `BaseApp`，管理生命周期、事件订阅 (`subscribe_event`)、布局注册。
- `ktem.pages`: 页面逻辑（`chat` 智能问答、`index` 文件索引管理、`resources` 模型资源配置、`settings` 系统参数）。
- `ktem.reasoning`: 将底层 RAG Pipeline 转换为 Gradio 可交互的 Event Stream。

## 5. RAG 数据流与工作机制

### 5.1 文档索引构建流程 (Indexing Phase)
```
上传 PDF/文档 ➔ 多模态解析器 (Docling/PyMuPDF) ➔ 文本与图表 Chunk 切片
                      │
                      ├──➔ 向量化 (text-embedding-v4) ➔ 存入 ChromaDB 向量库
                      └──➔ 存入 LanceDB 文本库 (用于 BM25 关键词检索)
```

### 5.2 问答检索响应流程 (Query & Generation Phase)
```
用户提问 ➔ 问题改写/拆解 (Rewrite/Decompose Pipeline)
                │
                ├─➔ 向量语义检索 (ChromaDB Vector Search) ──┐
                └─➔ 全文关键词检索 (LanceDB BM25 Search)  ──┴─➔ 混合检索融合 (Hybrid Search)
                                                                       │
                                                                       v
                                                             可选重排序 (Rerank)
                                                                       │
                                                                       v
                                                             构造上下文 (Evidence Format)
                                                                       │
                                                                       v
                                                     结合 Vision/LLM (qwen3-vl-235b-thinking)
                                                                       │
                                                                       v
                                                     流式输出回答 + PDF.js 高亮出处定位
```

## 6. 知识图谱引擎 (GraphRAG & LightRAG)

针对跨文档实体关系推理与宏观归纳问题，Kotaemon 在 [`libs/ktem/ktem/index/file/graph/`](file:///d:/selfAiProject/kotaemon/libs/ktem/ktem/index/file/graph/) 提供了知识图谱索引与检索能力。

### 6.1 Microsoft GraphRAG 实现
- **索引流水线 (`GraphRAGIndexingPipeline`)**:
  - **跳过普通分块**: 设置 `pipeline.splitter = None`，保证语义完整性；
  - **调度官方引擎**: 自动拉起 `python -m graphrag.index`；
  - **实体/关系提取与 Leiden 聚类**: LLM 遍历文本单元抽取实体节点与关系边，利用 **Leiden 聚类算法** 划分层级社群（Hierarchical Communities），并生成层次化社群摘要报告（Community Reports）；
  - **持久化**: 输出 `create_final_nodes.parquet`、`create_final_relationships.parquet`、`create_final_community_reports.parquet`。
- **检索流水线 (`GraphRAGRetrieverPipeline`)**:
  - **LanceDB 实体语义检索**: 将实体描述向量化存入 LanceDB，Query 到达时检索最相似的 Top-K 实体；
  - **局部混合拓扑检索 (`LocalSearchMixedContext`)**: 沿图拓扑扩展 1-hop/2-hop 关系边、关联原始段落与社区报告；
  - **双通道输出**: 文档通道返回 Markdown 结构化证据；可视化通道通过 NetworkX + Plotly 渲染力导向图（`visualize_graph`）。

### 6.2 LightRAG 轻量化增量图谱架构
- **实现位置**: [`libs/ktem/ktem/index/file/graph/light_graph_index.py`](file:///d:/selfAiProject/kotaemon/libs/ktem/ktem/index/file/graph/light_graph_index.py) 及 [`lightrag_pipelines.py`](file:///d:/selfAiProject/kotaemon/libs/ktem/ktem/index/file/graph/lightrag_pipelines.py)
- **原生增量写入**: 检测 `graph_chunk_entity_relation.graphml` 是否存在，已有图谱直接调用 `graphrag_func.insert()` 进行增量合并，免去传统 GraphRAG 全量重构的昂贵代价。
- **Dual-Level 双层检索体系**:
  - **Local 模式**: 召回高相关性实体、直连边与原始切片，应对具体事实查询；
  - **Global 模式**: 检索全局概念聚类与宏观关系，应对大跨度开放式归纳总结；
  - **Hybrid 模式**: 融合局部细节与宏观概念，达到最全面的知识覆盖。
- **通用模型适配与缓存加速**:
  - 封装通用适配器 `get_default_models_wrapper`，直接复用已配置的国产模型（如通义千问）；
  - 内置带请求指纹的 Key-Value 缓存（`hashing_kv`），重复调用零 Token 消耗。

## 7. 异步双流思维导图引擎 (Markmap)

Kotaemon 在输出答案的同时，能够实时呈现类似 XMind 的交互式脑图，其核心由异步多线程并发、Prompt 语法转译与前端 Markmap 动态渲染构成。

### 7.1 全链路工作流程
```
用户提问 ➔ QA Pipeline 启动
   │
   ├── [主线程] 流式生成回答 ➔ LLM.stream() 逐字打字机推送到前端 Chat 窗口 (TTFT 零等待)
   │
   └── [后台线程] 并发生成脑图 ➔ threading.Thread(target=mindmap_call).start()
          │
          ├── 调用 MapGPT: 从 Context 提取 PlantUML 树形语法 (@startmindmap ... @endmindmap)
          ├── 语法转译: convert_uml_to_markdown() 将 * 转为 Markdown 层级 (#, ##, ###)
          └── 注入模板: 封装至 <div class="markmap"><script type="text/template">...
                  │
                  v
       主回答完成 ➔ thread.join() 汇合 ➔ 通过 Document(channel="info") 推送至前端侧边栏
                  │
                  v
       前端 Markmap (D3.js 驱动) 自动检测 DOM 并生成动态 SVG 矢量思维导图
       (支持滚轮缩放、拖拽平移、节点收缩展开、[Expand] 全屏浏览与 [Export] 独立 HTML 导出)
```

## 8. 可信 AI、可观测性与高级评测体系

为打破传统向量 RAG 的“黑盒化”痛点，并解决低召回相关度下的模型幻觉问题，系统设计了完备的可观测性与实时评测护栏。

### 8.1 UMAP 高维语义空间降维可视化 (`CreateCitationVizPipeline`)
- **实现位置**: [`libs/ktem/ktem/utils/visualize_cited.py`](file:///d:/selfAiProject/kotaemon/libs/ktem/ktem/utils/visualize_cited.py)
- **技术原理**:
  - 借鉴 [RAGxplorer](https://github.com/gabrielchua/RAGxplorer) 架构，引入 **UMAP（统一流形逼近与投影）** 算法；
  - 实时将 1024 维的高维 Dense Embeddings 拟合并投影至二维拓扑平面；
  - 结合 **Plotly** 生成交互式散点图，直观标记出四类核心语义分布：
    - `Original Query` (原始提问，红色十字)
    - `Retrieved` (本次命中召回切片，绿色圆点)
    - `Chunks` (知识库全量背景片段，半透明蓝色圆点)
    - `Sub-Questions` (拆解后的子问题，紫色星号)
  - 让用户与工程师直观“看见”语义相似度与空间聚类形态，使黑盒检索具备极高的可解释性与调试效率。

### 8.2 TruLens 实时置信度评测与防幻觉护栏 (`LLMTrulensScoring`)
- **实现位置**: [`libs/kotaemon/kotaemon/indices/rankings/llm_trulens.py`](file:///d:/selfAiProject/kotaemon/libs/kotaemon/kotaemon/indices/rankings/llm_trulens.py) 与 [`simple.py`](file:///d:/selfAiProject/kotaemon/libs/ktem/ktem/reasoning/simple.py#L251-L255)
- **技术原理**:
  - 落地学术界金标准 **RAG Triad（三元组评测）** 准则中的 **Context Relevance（上下文相关性）** 评估；
  - 通过多线程并发（`ThreadPoolExecutor`）运行轻量级 LLM-as-a-Judge 裁判模型，对召回的各个 Context 片段进行 0~10 分的严格相关度打分；
  - **实时防幻觉熔断机制**: 当最高上下文相关性得分低于安全红线阈值（`CONTEXT_RELEVANT_WARNING_SCORE = 0.3`）时，系统在前端实时拦截并向用户发出高危预警：`"WARNING! Context relevance score is low. Answer might be inaccurate or hallucinated!"`，从机制上杜绝虚假信息的企业商用风险。

### 8.3 确定性字符级引用溯源对齐 (`CiteEvidence` Function Calling)
- **实现位置**: [`libs/kotaemon/kotaemon/indices/qa/citation.py`](file:///d:/selfAiProject/kotaemon/libs/kotaemon/kotaemon/indices/qa/citation.py) 与 [`citation_qa.py`](file:///d:/selfAiProject/kotaemon/libs/kotaemon/kotaemon/indices/qa/citation_qa.py#L296-L315)
- **技术原理**:
  - 废弃不可靠的“模型自填角标”模式，通过 Pydantic 强类型 schema 声明函数 `CiteEvidence(evidences: List[str])`；
  - 强制约束 LLM 在作答时必须调用此 Tool，且抽取的引用必须是原文中**完全吻合的原文字符子串 (Substring, <=15 words)**；
  - 算法模块调用 `find_text(quote, doc.text)` 计算出精准的字符级起始与终止偏移量（Character Spans: `[start, end]`），联动前端 PDF.js 实现原文字符与几何坐标（BBox）的绝对对齐与精确高亮。

### 8.4 动态上下文示例检索增强 (`FewshotRewriteQuestionPipeline`)
- **实现位置**: [`libs/ktem/ktem/reasoning/prompt_optimization/fewshot_rewrite_question.py`](file:///d:/selfAiProject/kotaemon/libs/ktem/ktem/reasoning/prompt_optimization/fewshot_rewrite_question.py)
- **技术原理**:
  - 将海量优质改写样本库（`rephrase_question_train.json`）构建为动态向量索引；
  - 用户发起提问时，先通过向量检索召回与当前问题语法模式最匹配的 Top-K 示例（Demonstrations），动态拼装入 Prompt 的 Few-shot 示例槽中，实现从“固定静态 Prompt”到“自适应动态上下文学习（Dynamic In-Context Learning）”的算法升级。

## 9. 企业级外部工具与协议中枢 (MCP & Web Search)

为了满足企业跨业务系统协同与获取外部实时信息的需求，系统集成了下一代开放协议与公网搜索能力。

### 9.1 Model Context Protocol (MCP) 原生集成
- **实现位置**: [`libs/ktem/ktem/mcp/manager.py`](file:///d:/selfAiProject/kotaemon/libs/ktem/ktem/mcp/manager.py) 与 [`kotaemon/agents/tools/mcp/`](file:///d:/selfAiProject/kotaemon/libs/kotaemon/kotaemon/agents/tools/mcp.py)
- **技术原理**:
  - 原生支持 Anthropic 发起的标准化工具协议 **MCP (Model Context Protocol)**；
  - 基于 SQLite `MCPTable` 实现企业外部微服务配置的动态持久化与热插拔管理（CRUD）；
  - 通过 JSON-RPC 协议标准与外部进程（Stdio）或远程服务（SSE / HTTP）通信，将企业内部数据库、CRM/ERP 接口动态包装为具备 `[MCP]` 标识的标准化 Agent Tools，与本地知识库检索形成统一编排。

### 9.2 本地私有库与公网实时搜索混合外挂
- **实现位置**: [`libs/kotaemon/kotaemon/indices/retrievers/jina_web_search.py`](file:///d:/selfAiProject/kotaemon/libs/kotaemon/kotaemon/indices/retrievers/jina_web_search.py) 及 [`tavily_web_search.py`](file:///d:/selfAiProject/kotaemon/libs/kotaemon/kotaemon/indices/retrievers/tavily_web_search.py)
- **技术原理**:
  - 集成 Tavily Search 与 Jina DeepSearch API，支持提取无噪声的纯洁版 Markdown 网页正文；
  - 当私有文档库未命中答案或用户主动发起全局探索时，自动无缝触发公网多路召回，彻底打破私有 RAG 系统知识库截止日期的壁垒。

## 10. 数据存储架构

项目中所有持久化数据均储存在本地 `ktem_app_data/user_data/` 目录中：

| 存储名称 | 存储路径 | 技术选型 | 数据类型 |
| :--- | :--- | :--- | :--- |
| **向量数据库** | `user_data/vectorstore/` | **ChromaDB** (`chroma.sqlite3`) | 1024 维 Dense Embeddings |
| **文档检索库** | `user_data/docstore/` | **LanceDB** (`index_1.lance`) | 文本切片、原始 Chunk、BM25 倒排索引 |
| **图数据存储** | `user_data/graphrag/` / `lightrag/` | **GraphML + Parquet + LanceDB** | 实体节点、关系边、社区报告、图拓扑结构 |
| **原始文件库** | `user_data/files/` | **文件系统** | 原始 PDF/WORD 文件（供阅读器加载） |
| **应用数据库** | `user_data/sql.db` | **SQLite3** | 用户账号、对话历史、会话列表、MCP 注册配置、模型 Key 配置 |

## 11. 环境与配置管理

1. **`.env` 文件**: 用于初始化配置，包括 `OPENAI_API_BASE` (如阿里云百炼端口)、`OPENAI_API_KEY`、`OPENAI_CHAT_MODEL` 及 `HF_ENDPOINT` 镜像等。
2. **动态数据库配置**: 初次运行后，系统会将配置写入 `sql.db`，后续支持在 Web UI 的 **模型资源配置 (Resources)** 界面中随时可视化修改与切换模型，无需重启服务。
